# B3 YSM resource distribution and compatibility projection

Backend predecessor: `1c6d8431ead6b6bcdf276bc41b6b48c14dd7ec8f`.
Matching client code: `ca898e099417cb6563c7c9daf7f45d05b730fc67` (client adapter
implementation remains B5; this checkpoint updates client progress documentation).

The resource adapter now accepts Figura compressed NBT and the existing filtered
YSM distribution package, also compressed NBT. Model type distinguishes plain
and encrypted YSM. Raw package, content and schema identities remain separate;
YSM requests require 32-byte content/schema identities. The server checks the
declared content identity against the portable package identity; it does not
reconstruct the client's plain source tree or execute its runtime schema.

`service/package.rs` scans NBT without building a model tree or allocating byte
arrays from untrusted lengths. The decompressed limit is 256 MiB, individual
resources 32 MiB, ciphertext 64 MiB, nesting 64, list entries 4096 and total NBT
nodes 262144, with a ten-second inspection deadline. Duplicate compound keys,
invalid types/lengths, truncated gzip and identity mismatches fail closed.
Encrypted packages retain the original ciphertext, checked by streaming hash;
only the existing portable metadata fields are accepted. No decryption code,
key storage or model execution is introduced.

Both public protocol adapters transfer file bodies through raw HTTP. Legacy PUT
retains its route, successful response and configured route body limit, but now
streams to a unique staging file, validates before replacement and cleans up
failed/cancelled requests. Legacy GET and protobuf GET stream the selected blob.
Legacy imports use a bounded file snapshot and streaming hashes rather than
reading a complete package into memory. Small writes and administrative legacy
writes are validated and atomically renamed. Concurrent upload admission is
shared across Figura requests and protobuf grants, at most two per account;
cancellation releases its permit. Protobuf size/hash and container failures
cannot become equipable assets and remove temporary files.

YSM equipment sets the primary slot and clears Figura compatibility by default.
`retain_figura_compatibility` retains the previous independent Figura slot.
Original Figura clients see only this slot, or an empty equipment list and 404.
Extended Figura clients explicitly send `x-omnimorph-models: ysm` to profile and
download routes to select the actual primary; B5 will wire this header into the
client adapter. Temporary-slot responses also enforce the capability. An old
format YSM upload is classified into the same typed index. Deletion clears
references and keeps the existing cross-protocol notifications.

Validation uses synthetic containers and identities, never private models:

- `cargo test --locked --offline`: nine tests PASS. The real loopback HTTP/WS
  suite now covers both public file adapters with Figura/plain/encrypted bytes,
  raw hash equality, content identity distinct from raw identity, both equipment
  projection choices, old-client denial, deletion 404 and repeated commit.
- Failure probes cover conflicting grant reuse, shared upload concurrency,
  oversized/truncated/wrong-hash transfers, declared model mismatch, temporary
  file cleanup, and a TCP disconnect during an unfinished chunked legacy body.
  A live legacy upload consumes the protobuf allowance; cancelling it restores
  that allowance. Two protobuf grants also block a legacy upload.
- Test-only HTTP stream capture records route, method, content type, byte count
  and SHA-256 without buffering bodies or recording credentials. It verifies
  the actual raw file digests on both upload routes and separate protobuf RPC
  requests. Files are not encoded into protobuf messages or WS frames.
- Container tests cover plain/encrypted classification, a smaller decompression
  budget, truncation and rejection of private fields in encrypted output.
- `cargo check --locked --offline` and `cargo build --release --locked --offline`:
  PASS after the final source changes.

This proves backend container/transport behavior, not that the synthetic cipher
fixture is decryptable. Real client loader/crypto corpus validation remains B5/B8.
Public HTTPS deployment and real-game observation remain separately recorded
acceptance items. The wire schema and its release digest are unchanged.
