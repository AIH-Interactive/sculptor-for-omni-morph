# B1 shared services and legacy adapter

Client implementation: `a69050c4e6ae214e8416e6f626999852614b14b7` (B0; no client code changes in B1).
Backend predecessor: `ea5a05dce7328819e93b042cba0991af20cd89ce`.

Shared service boundaries now own authenticated identity checks, legacy resource
I/O, equipment notifications, typed business events and connection registration.
Figura adapters retain their existing routes and frame encoders. Internal and v1
legacy resource writers also use the shared writer, so small uploads finish
writing before success instead of dropping an unflushed Tokio BufWriter.

Each WebSocket receives an independent connection ID. Closing a transport removes
only that ID, and never revokes an account's other tokens. Multiple valid device
tokens coexist. Bans and owner notifications target all account connections.
Subscription registration is idempotent; unsubscribe removes and aborts its worker.
Business Ping arguments remain opaque; legacy administrative raw frames stay
explicitly marked as legacy input. Protobuf encoding is a B2 adapter responsibility.

Validation: `cargo test --locked` passes 5 tests, including the unchanged B0 wire
vectors and real HTTP/WS lifecycle in an isolated store. The lifecycle checks:

- denied and invalid-token uploads, HTTP body size rejection, raw upload/download
  equality including packages smaller than the previous write buffer;
- two tokens/connections for one owner, separate observer, normal and high-bit
  Ping function IDs with unchanged opaque parameters and echo;
- duplicate subscribe, unsubscribe/resubscribe, exact equipment/delete frames;
- normal old-connection close, reconnect and abrupt TCP drop while the other
  connection and both HTTP tokens remain valid;
- deleted resource returns 404 and the old profile projects an empty equipped list;
- connection cleanup and registry-level repeated removal / account fanout.

`cargo build --locked`: PASS (actual backend executable; one unused test-count
helper warning). No client code
changed, so the B0 Fabric build remains the matching client compilation evidence.
Versioned resource storage, new protocol limits and recovery remain B2-B4 work.
