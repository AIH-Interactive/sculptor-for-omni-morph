The existing EnumConfig widget exposes exactly Figura Cloud and Protobuf. Disk
values are stable FIGURA_CLOUD/PROTOBUF names, with explicit 0/1 numeric migration.
The initial, missing-field, reset and unknown-value choice is Protobuf. Unknown
values produce a controlled diagnostic without echoing their contents or resetting
unrelated settings. Existing server addresses are preserved; the additive setting
does not bump the existing config version or replace the domain.

Changing the applied choice disconnects the previous connection, cancels its work,
advances epoch and schedules fresh authentication. Temporary edits/undo do not
reconnect. A tick also detects changed persisted protocol/address values. Both
HTTP and WS use the selected adapter, with one model-state publication path.

Before requesting a Minecraft identity token for Protobuf, the client probes the
configured origin's capability endpoint. Unsupported routes/content/version or
missing required capability give a localized manual Figura Cloud selection hint.
There is no automatic legacy retry/domain substitution. Capability discovery is
revalidated when the actual scoped session connects. Network/TLS failures remain
failures and do not authorize fallback. Failed connection and disconnect preserve
local models and the local selection; backend availability is not a loader gate.
