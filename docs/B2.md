# B2 Protobuf general backend capabilities

Matching client: `11ff1b4c5dec2286747bd507f4280b2b265b5f10` (protocol generation
and vectors from B0; subsequent client changes are documentation only).
Backend predecessor: `b1b9b1ef850d67c873e4ff11fc1721ec34937a48`.

The main backend now serves capability discovery, authenticated protobuf RPC,
binary WebSocket with `omnimorph.cloud.v1`, and separate raw HTTP file routes.
Hello advertises only the implemented Figura capability. YSM resources and
recovery remain B3/B4; the production client adapter remains B5.

Authentication derives the owner from the existing identity token. Scoped tokens
are bound to this persistent instance, protocol major and connection epoch,
expire after one hour, and revalidate the source identity. HTTP and WS use the
same scope. Closing one of multiple connections cannot revoke the others.
Tokens are passed in headers, never resource or WebSocket URLs.

Profiles include badges, permissions, version and equipped resources. ServerInfo
contains configured upload limits, avatar count, versions and MOTD. The shared
event hub bridges Figura Ping arguments without decoding or changing them;
each transport encodes its own frame. Equipment/delete notifications reach
mixed protocol subscribers. Administrative legacy raw frames remain legacy-only.

The versioned manifest under `AVATARS_VAR/cloud-v1` records resource revisions,
equipment, deletion tombstones and bounded operation results. Blobs are immutable
and keyed by raw SHA-256. The metadata transaction is synchronized and atomically
renamed only after the file is published. Upload grants alone are not equipable.
Raw PUT checks exact size/hash with bounded streaming, timeout and failed-file
cleanup. GET streams the original compressed NBT bytes. Legacy Figura identity
remains SHA-256(Base64(raw bytes)), distinct from raw identity. Old `.moon`
resources are imported lazily; legacy writes/deletes use the shared resource
index. The historical self-profile temporary-slot probe is preserved.

Equipment and deletion validate expected revisions and canonical operation UUIDs.
Completed operation results are retained for one hour, at most 128 per owner;
exhaustion returns LIMIT_EXCEEDED. Asset history is bounded to 1024 revisions.
Account budgets are shared across transports: 32 messages/second, 262144
bytes/second, eight connections and eight scoped sessions. Subscriptions are
bounded to 128 and pending uploads to two per owner, with a 120-second grant.
Wire inspection precedes generated decoding and limits envelope size, repeated
entries, nesting, strings, valid enums and finite numeric values.

Validation on Windows, using the main crate and locked offline dependencies:

- `cargo check --locked --offline`: PASS.
- `cargo test --locked --offline`: PASS, eight tests. The real local HTTP/WS
  baseline calls both legacy and mixed-protocol lifecycles, including legacy
  upload → protobuf profile/download, protobuf upload/commit/equip → legacy
  download, unchanged Ping parameters in both directions, notifications,
  idempotent retry, conflicts, deleted-resource 404, owner forgery, oversized
  payloads, unknown major, wrong epoch and mismatched bearer/envelope session.
- Registry tests cover account budgets, connection admission and slow recipients.
  Wire tests cover pre-decode budgets, unknown fields, truncation, duplicate
  fields, integer wrapping and NaN/Infinity rejection.
- `cargo build --release --locked --offline`: PASS, optimized executable.

Tests use isolated temporary storage, synthetic identities and loopback sockets.
They do not prove a deployed HTTPS endpoint or a real game client; these remain
B7/B8 evidence. No client code changes in B2; B0 Fabric compilation remains the
matching client build evidence. B3 starts only after both repository checkpoints
are pushed and their remote SHAs verified.
