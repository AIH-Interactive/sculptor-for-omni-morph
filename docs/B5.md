# B5 production Java adapter integration

Backend predecessor: `03b740a7f2a905775c9cc2a83f3d551021261a6b`.
Client predecessor: `fd401ea054b8daff72e4b0f2e7a4cbe5fe1acf29`.
The paired client B5 checkpoint contains the production adapters and their entry
point integration. This backend checkpoint adds only the cross-language test gate
and its documentation; backend production behavior and the wire schema are unchanged.

`src/api/protobuf/tests/java_client.rs` optionally runs the actual compiled client
adapters against the same random-port loopback listener and isolated storage used
by the frozen backend baseline. It adds two synthetic authenticated accounts and
synthetic Figura/plain/encrypted NBT distribution fixtures. The encrypted fixture
is intentionally not decryptable: this gate proves raw transport/typed identities,
while the client corpus/crypto gates prove actual decoding separately.

Run from the client root with JDK 25 and the standard foreground logging pipeline:

1. `gradlew.bat :common:test :common:writeCloudIntegrationClasspath --console=plain`.
2. In the backend PowerShell, set `OMNIMORPH_CLIENT_CLASSPATH_FILE` to the absolute
   client `build/cloud-integration-classpath.txt` path; retain JDK 25 JAVA_HOME.
3. `cargo test --locked --offline -- --nocapture`.

The Rust harness starts Java as a foreground child, inherits stdout/stderr, waits
for exit, applies a 120-second deadline with kill-on-drop, and verifies both socket
sessions clean up. Java arguments use a temporary argument file to avoid Windows
command-line length limits. All temporary fixture/argument files are removed.
Without the explicit classpath variable, the ordinary backend suite keeps its
self-contained Rust gates; that run alone does not claim cross-language B5 PASS.

The Java gate covers both directions, Figura Cloud -> Protobuf and Protobuf ->
Figura Cloud, each with Figura/plain YSM/encrypted YSM raw HTTP bytes, profile and
cache reference agreement, upload/commit/equip/delete, authenticated owner and
opaque Ping arguments/echo. YSM cases add typed snapshot/delta presence, short
instantaneous effects, exact source retry without rebroadcast, live events during
periodic full snapshots, and re-subscription materialized recovery without old
event replay. No model file enters a protobuf body or socket message.

Client entry points now use the common business interface. The old adapter keeps
HTTP routes and real M7 framing with an explicit YSM capability header; the new
adapter uses generated formal fields. The existing output filter and model loader
remain authoritative, including ciphertext-only encrypted distribution. Runtime
state application still validates content/schema/index/authority and performs
no observer publication. HTTP requests, socket buffers, outbound control queues,
game-thread callbacks and model-load queues have bounded lifetime and budgets;
connection retirement cancels work and rejects late publication. Cache references
include origin/instance, owner, revision/hash and format/type identities available
to that protocol. Lower negotiated protobuf budgets cannot raise local ceilings.

Configuration controls/defaults belong to B6. This B5 checkpoint keeps the existing
normal Figura Cloud choice and exposes both adapters through the factory/programmatic
connection entry point; it does not claim the B6 default-Protobuf UI is delivered.
URI/debug/security and public deployment acceptance remain the subsequent gates.
Real game/GUI observations remain SKIPPED/MANUAL_BY_USER, not inferred from CPU tests.

Final command results are recorded in the paired client progress document after
all B5 gates complete, before either repository's checkpoint is pushed.
