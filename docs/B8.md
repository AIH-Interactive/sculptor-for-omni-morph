## Changes and automated evidence

Storage removes expired-process uploads/*.part only after accepting its schema.
Unknown schemas fail without deleting their upload files or rewriting metadata.
Immutable blobs are retained, including an unreferenced blob from an interrupted
commit. No legacy .moon conversion, private-key storage or model decryption is
introduced. Startup requires exclusive ownership of its data directory.

The parent test launches separate Rust processes with a temporary store, performs
the production lazy legacy import three times, and checks the same revision/raw
bytes/hash. It commits Figura compatibility, a primary YSM resource, deletion
tombstones, a complete YSM snapshot and event watermark. A test-only hook pauses
the real transaction after candidate sync and before atomic replacement. The
parent kills that process, verifies the committed manifest stayed unchanged,
then starts new processes repeatedly. They recover the previous equipment,
snapshot/watermark and tombstones, reject unpublished resources, clean incomplete
uploads and preserve legacy bytes. Unknown-version rejection and recovery after
restoring the accepted schema are also tested. The crash hook is absent from
production builds.

The actual baseline backend at `28fb81ed177bf24ae616eb68e9c6220f0bd60a4a`
was built independently from its archived source and started against the migrated
temporary data. A local synthetic authentication provider drives its original
auth/profile/download APIs; the current production Figura Cloud adapter also
connects, reads raw Figura bytes and exercises opaque Ping. Hashes of every
cloud-v1 file and the legacy package stay unchanged. Restoring the new process
retains primary YSM, tombstones and recovery state.

Config.toml supports `protobufEnabled = false` with a backend restart. Missing
configuration defaults to true. Actual new production processes with the flag
off/on verify capability/RPC/WS route availability while the legacy routes and
stored new data remain intact. Client fallback remains explicit and persisted.

Backend authentication traces formerly exposed token/response details. They now
emit presence/status/counts or stable failure categories. HTTP spans omit URI
queries. Actual production trace logs are inspected for a rejected synthetic
token and the newly issued auth response/session token; neither is present.

The Java gate covers all four source/observer protocol pairs, each with Figura,
plain YSM and opaque encrypted YSM packages: 12 cases. It verifies raw HTTP bytes,
resource/cache projection, upload/equip/delete, authenticated Ping/echo,
snapshot/delta presence, live short actions, retry deduplication and late baseline
watermarks without replaying old one-shot effects. Independent Ping producers are
matched by owner/id; the test does not impose a nonexistent cross-socket order.
The encrypted fixture is not claimed to be a decryptable real model; real crypto
and loader validation is performed separately on the dynamic client corpus.
